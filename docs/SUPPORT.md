# 故障反馈

问题发生后，尽量先导出反馈包，再重启程序；重启会重置当前会话的运行统计。

1. 打开“设备与诊断…”并点击“导出反馈包”。该操作独立于同步线程，不发送音响HID查询或设置，可以在同步时执行。
2. 程序会打开保存文件夹。可先解压检查ZIP内容。
3. 点击“反馈问题…”进入GitHub模板，填写软件版本、游戏、发生时间、操作步骤、预期和实际表现，将ZIP拖入描述框后自行提交。也可访问[问题反馈入口](https://github.com/nj-yzf/HaloTruckDash/issues/new?template=bug_report.yml)。

请补充是否同时运行SimHub或其他音响控制程序，以及是否拔插USB、切换输入模式。显示异常可附音响照片；界面截图注意避免露出其他个人内容。

## 反馈包内容

- `report.json`：反馈编号、UTC导出时间、系统与版本、USB接口元数据、遥测快照、同步选项摘要、连接/失败/同步计数、最后成功时间和当前操作耗时；还包含附带及已选游戏目录中遥测插件的只读校验结果。
- `logs/`：当前日志及最多三份备份，各取最后256KB。旧日志中的常见本机/网络路径、已知USB标识和旧版屏幕文字日志也会再次遮蔽。
- `README.txt`：反馈步骤说明。

不会打包settings.json、保存布局、设备验证记录或屏幕恢复文件，也不会自动上传。自动脱敏针对路径和程序已知的设备标识，不等于能识别任意第三方错误信息中的所有个人内容；公开提交前仍可检查文件。

数据默认位于程序旁`data/`，无法写入时回退到`%LOCALAPPDATA%/HaloTruckDash/data/`。界面打不开时可执行：

```powershell
.\HaloTruckDash.exe --feedback
```

生成文件位于实际数据目录的`feedback/`。命令行导出没有界面进程的实时计数，可凭近期日志回看故障。单独的`--diagnose`仍只导出diagnostics.json，内容少于反馈包。

## 日志与限制

`dashboard.log`采用UTF-8，记录时间、级别和线程名。每份约2MB，最多保留`.1`至`.3`三份备份；同步时每分钟记录一次统计摘要，状态不变时不逐帧记录。包含启动/退出、同步开始/停止、遥测状态变化、连接与重试、屏幕状态修复、恢复、设备验证、插件安装及Python异常调用栈。

程序会记录未处理的主线程、后台线程和Tk回调异常；后台初始化失败也会释放退出等待。强制终止、断电或底层驱动/原生运行库崩溃未必能留下Python异常记录。若音响操作卡住，反馈包可以显示操作名称及持续时间，但不能替代驱动级跟踪，也无法终止卡住的原生USB调用。
